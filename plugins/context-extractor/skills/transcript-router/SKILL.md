# Skill: Transcript Router

## Правила маршрутизации

1. **01_Франшиза** — зарезервирована исключительно для общего контекста Франшизы. Функциональные процессы (продажи, ИТ, логистика и т.д.) туда не кладутся, даже если они упоминаются в контексте франшизной сети.

2. **Разные самостоятельные процессы** — каждый получает отдельный файл, даже если оба относятся к одной и той же папке.
   - *Пример независимых процессов (одна папка):* «Процесс розничных продаж» И «Модель компенсаций в розничных продажах» → 2 отдельных файла в `02_Розничные продажи`.
   - *Пример подпроцесса (не независимый):* «ИТ-поддержка» охватывает подпроцесс «Тикетирование ИТ-запросов» → 1 файл, подпроцесс описан внутри него.

3. **Пересечение «Франшиза + функция»** — создаются ДВА файла: один в `01_Франшиза`, другой в соответствующей функциональной папке. Пример: ИТ-поддержка в локациях партнёров → файл в `01_Франшиза` + файл в `08_ИТ`.

   **Именование парных файлов:** чтобы не было неоднозначных вики-ссылок в Obsidian, в заголовок и имя каждого из двух файлов добавляется суффикс-уточнитель в скобках:
   - Файл `01_Франшиза` получает суффикс `(Франшиза)`:
     заголовок → `# ИТ-поддержка партнёрских точек (Франшиза)`,
     файл → `ИТ-поддержка партнёрских точек (Франшиза).md`
   - Файл в функциональной папке получает суффикс = название папки без номера:
     заголовок → `# ИТ-поддержка партнёрских точек (ИТ)`,
     файл → `ИТ-поддержка партнёрских точек (ИТ).md`

   Суффикс обязателен всегда при парных файлах, независимо от внешней схожести заголовков.

4. **Процесс охватывает две функциональные области** — выбирается та папка, в которой процесс описан подробнее. Дублировать один и тот же файл в два функциональных раздела нельзя.

   > **Пересечение трёх областей (Франшиза + два функциональных раздела):** применяется Правило 3 — создаётся файл в `01_Франшиза` + один функциональный файл. Для второго функционального раздела применяется Правило 4: выбирается тот, где процесс описан подробнее. **Максимум 2 файла на один процесс**, даже при трёхстороннем пересечении. Если транскрипт содержит несколько независимых процессов — каждый получает до 2 файлов.

## Как выбрать сценарий

Перед маршрутизацией выполни поиск по рабочему пространству:

1. Используй `Glob` по функциональным папкам (`02_Розничные продажи/`, `08_ИТ/` и т.д.) для поиска `.md`-файлов, которые покрывают данный процесс.
2. Если найден файл, описывающий тот же процесс или систему — применяй **Сценарий А** (обновление).
3. Если ни один существующий файл не покрывает процесс — применяй **Сценарий Б** (создание нового).

> Поиск проводится только в функциональных папках. Папка `_review/` при поиске не учитывается.

---

## Сценарий А: Обновление существующего файла

Применяется, когда транскрипт дополняет или уточняет информацию, уже зафиксированную в существующем файле контекста.

**Правила:**
- **Уточнение/детализация:** если новый транскрипт добавляет детали или исправляет существующее — редактируй текст по месту, встраивая новые факты в соответствующие разделы. Не добавляй отдельный блок в конец файла.
- **Противоречие:** если новый транскрипт противоречит уже зафиксированному контексту — не разрешай противоречие самостоятельно; добавь его в пакет вопросов пользователю вместо слияния.
- Старая важная информация не удаляется, если только в новом транскрипте она явно не отменена.

### ФОРМАТ ВЫВОДА ДЛЯ ОБНОВЛЕНИЯ

```
В файле **[Название существующего файла].md** замените блок под заголовком `[Название заголовка]` на следующий текст:

[Обновлённый текст раздела с вплетёнными новыми фактами]

---
Что изменено: [краткое перечисление ключевых правок для проверки пользователем]
```

> Если несколько заголовков могут подойти — выбирай наиболее специфичный (узкий). Например, `## 2.3 Тикетирование` предпочтительнее `## 2. ИТ-поддержка`.

---

## Сценарий Б: Создание нового файла

Применяется, когда транскрипт описывает процесс или систему, которые ещё не зафиксированы ни в одном из существующих файлов контекста.

**Правила:**
- Существующие файлы используются только как ориентир по стилю и уровню детализации.
- Новый файл создаётся по формату ниже.
- Файл сохраняется в `_review/<NN_Папка>/<Заголовок>.md` для проверки перед переносом в основное рабочее пространство. Используй **полное** имя папки (например, `_review/08_ИТ/`). Имя файла — точная копия заголовка документа (`# ...`) на кириллице, с сохранением регистра. Пример: заголовок `# ИТ-поддержка партнёрских точек` → файл `ИТ-поддержка партнёрских точек.md`. **Транслитерация и kebab-case строго запрещены** — иначе вики-ссылки `[[...]]` в Obsidian не разрешатся. Если поддиректория ещё не существует — создай её.

### ФОРМАТ ВЫВОДА ДЛЯ НОВЫХ ФАЙЛОВ

```
---
folder: [Точное название папки из списка выше]
---

# [Суть описанной системы или процесса — краткий заголовок]

## 1. Текущее состояние (As-Is)
[description]

## 2. Ключевые роли и системы
* [[Каноничная Роль|Роль в тексте]] — зона ответственности
* [[Каноничная Система|Система в тексте]] — функция

## 3. Правила и Взаимосвязи
* [Факт или бизнес-правило]
* Зависит от: [[Сущность]]
* Влияет на: [[Сущность]]

## 4. Решения
* [Решение, принятое на совещании — конкретная договорённость, не план]

## 5. Открытые вопросы
* [Вопрос, поднятый на совещании и оставшийся без ответа]
```

> Разделы `## 4. Решения` и `## 5. Открытые вопросы` пропускаются, если в транскрипте нет соответствующих данных.
