# context-extractor

Плагин Claude Code для извлечения As-Is бизнес-контекста из транскриптов совещаний.

Положи транскрипт в `_inbox/` рабочей папки — плагин извлечёт процессы, роли, системы, правила, проблемы, решения, термины и открытые вопросы, задаст один пакет уточняющих вопросов, покажет план в Plan Mode и после твоего «ОК» запишет файлы в `_review/` (не в основную базу). Глоссарий ведётся отдельным sub-agent'ом, который точечно правит `glossary.md` и ловит дубли с нормализацией регистра.

## Установка

В Claude Code:

```
/plugin marketplace add SecondBrainProd/claude-context-extractor
/plugin install context-extractor@claude-context-extractor
```

Перезапусти Claude Code (`/exit`, потом `claude`). Проверь, что субагенты появились:

```
/agents
```

Должны быть `context-extractor` и `glossary-steward`.

## Где размещать рабочую папку (важно)

**Рекомендация: размести рабочую папку ВНУТРИ своего Obsidian-vault** (например, в подпапке `Контекст`). Причина — накопленный контекст должен быть виден агенту. Функциональные папки (`01_*`, `02_*`, …) это и есть твоя растущая база знаний. Если они внутри vault:

- агент через `Glob` видит всю накопленную историю и корректно работает по Сценарию А (дополняет существующие файлы, а не плодит дубли);
- перенос готового из `_review/` в `<папка>/NN_*/` — это копирование внутри того же vault, а не в отдельное хранилище;
- файлы и вики-ссылки `[[...]]` сразу живут в твоём Obsidian-графе.

Если держать workspace отдельно от vault (как `~/work/context-extractor`), то после ручного переноса файлов в основную базу агент перестаёт их видеть, и накопленный контекст для Сценария А теряется.

## Создание рабочей папки

На Windows из папки плагина:

```powershell
# Рекомендуется — внутри vault:
.\bin\create-workspace.ps1 -BasePath "C:\Users\<you>\ObsidianVault\Контекст"

# Или дефолтный путь вне vault (~\work\context-extractor):
.\bin\create-workspace.ps1
```

Скрипт создаст:
- `_inbox/` — куда класть транскрипты
- `_review/` — куда плагин пишет промежуточный результат
- `glossary.md` — пустая заготовка словаря канонических имён
- 19 функциональных папок (`01_Франшиза`, `02_Розничные продажи`, …, `19_Помещения`)
- `.claude/settings.json` — permission-правила

Никакой ручной правки путей в `settings.json` не нужно. Правила записаны как **project-relative** (`/_review/**`, `/glossary.md`, `/**`) — относительно папки, из которой ты запускаешь `claude`. Это работает одинаково и внутри vault, и отдельно, и не ломается на Windows/кириллице.

**Модель защиты.** В правилах НЕТ blanket-deny — в Claude Code приоритет `deny > ask > allow` (побеждает первое совпадение), поэтому deny на весь vault заблокировал бы и запись в `_review`. Защита держится на `defaultMode: plan` + узком allow-листе: агент пишет только в `_review/` и правит `glossary.md`; любая попытка записи в другое место vault → запрос подтверждения. Молча ничего не пишется, остальной vault не трогается без твоего «ОК».

Если 19 функциональных папок не подходят — отредактируй массив `$folders` в `bin/create-workspace.ps1` и `skills/transcript-router/SKILL.md` (там тот же список + правила маршрутизации).

## Повседневный сценарий

1. Положи транскрипт в `_inbox/` (`.md` или `.txt`).
2. Открой терминал в рабочей папке:
   ```
   cd ~/work/context-extractor
   claude
   ```
3. Запусти команду:
   ```
   /context-extractor:process-transcript
   ```
4. Ответь на пакет уточняющих вопросов.
5. Проверь план в Plan Mode → `approve`.
6. Файлы появятся в `_review/`, словарь обновится через `glossary-steward`.
7. Проверь заметки в `_review/` (поправь формулировки, если нужно) и запусти раскладку:
   ```
   /context-extractor:apply-review
   ```
   Команда покажет план переноса (что куда, что заменяется), после approve разложит заметки по функциональным папкам, снимет служебные `folder:`-метки и ревью-хайлайты `==…==`, очистит `_review/`. Так накопленный контекст остаётся в одном месте и виден агенту при следующих запусках (Сценарий А — дополнение существующих файлов). Ручной перенос по-прежнему возможен, если предпочитаешь.

## Структура плагина

- `agents/context-extractor.md` — извлекает 8 категорий из транскрипта, формирует пакет вопросов, готовит план.
- `agents/glossary-steward.md` — точечно правит `glossary.md`, ловит дубли через нормализацию (case-insensitive, дефисы/пробелы).
- `commands/process-transcript.md` — оркестратор цикла обработки транскрипта.
- `commands/apply-review.md` — раскладка проверенных заметок из `_review/` по папкам (финальный шаг цикла).
- `skills/transcript-router/SKILL.md` — правила маршрутизации по функциональным папкам, форматы вывода, сценарии «обновление vs создание», обработка пересечения «общий контекст + функция».
- `bin/create-workspace.ps1` — генерация рабочей папки для Windows.

Чтобы изменить правила маршрутизации, отредактируй `skills/transcript-router/SKILL.md` в кэше плагина (`~/.claude/plugins/cache/claude-context-extractor/context-extractor/<version>/`) — это обычный Markdown.
