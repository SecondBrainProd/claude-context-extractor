# `/context-extractor:process-transcript`

Оркестратор полного цикла обработки транскрипта.

---

## Шаг 1. Проверяем _inbox/

Используй `Glob` для поиска файлов в `_inbox/`.

- **Если пусто** → сообщи:
  ```
  _inbox/ пуста. Положи транскрипт (.md или .txt) в папку _inbox/ и запусти команду снова.
  ```
  → Стоп.

- **Если несколько файлов** → обрабатываем первый по алфавиту, напоминаем пользователю об оставшихся файлах.

---

## Шаг 2. Запускаем context-extractor

Диспатчи агента `context-extractor` на найденный транскрипт. Агент:

1. Читает `glossary.md`
2. Анализирует транскрипт
3. Формирует пакет вопросов
4. Ждёт ответов пользователя

---

## Шаг 3. Plan Mode — показываем план

После того как пользователь ответил на вопросы, context-extractor готовит план:

**Список файлов для СОЗДАНИЯ:**
| Путь в _review/ | Целевая папка | Заголовок |
|-----------------|---------------|-----------|
| …               | …             | …         |

**Список файлов для ОБНОВЛЕНИЯ:**
| Файл | Раздел | Суть изменений |
|------|--------|----------------|
| …    | …      | …              |

**Новые термины для glossary.md:**
| Каноническое имя | Синонимы |
|------------------|----------|
| …                | …        |

Plan Mode показывает полный план — пользователь проверяет и даёт approve.

---

## Шаг 4. Записываем файлы и обновляем словарь

После approve:

1. **context-extractor** записывает файлы в `_review/` (только туда, НЕ напрямую в функциональные папки)
2. Диспатчи агента **glossary-steward** с пакетом новых терминов — он правит `glossary.md` точечными Edit-ами

**Верификация — проверяй КАЖДУЮ заметку, не выборку.** После записи открой и сверь ВСЕ созданные/обновлённые файлы (а не 2-3 на пробу): число файлов совпадает с перечнем из инвентаризации; у каждой заметки заголовок `# ...` совпадает с именем файла; канонические ссылки `[[...]]` оформлены; разные as-is не слиплись в один файл. Если файлов много — пройди по всем, это машинная проверка, не экономь на ней.

---

## Шаг 5. Финальный отчёт

Выводим сводку:

```
✓ Обработан: [название транскрипта]

Создано в _review/:
  • [путь к файлу 1] → [целевая папка]
  • [путь к файлу 2] → [целевая папка]

Обновлено в _review/:
  • [имя файла] — [суть изменений]

Словарь glossary.md:
  • Добавлено терминов: N
  • Обновлено строк: M

Следующий шаг: перенеси файлы из _review/ в основной vault вручную.
```

Если в `_inbox/` остались необработанные файлы — напомнить запустить команду снова.
