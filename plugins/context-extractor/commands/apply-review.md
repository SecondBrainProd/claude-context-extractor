# `/context-extractor:apply-review`

Финальный шаг цикла: раскладывает проверенные заметки из `_review/` по целевым функциональным папкам. Запускается ПОСЛЕ того, как пользователь проверил содержимое `_review/` (поправил формулировки, снял вопросы).

---

## Шаг 1. Инвентаризация _review/

Используй `Glob` для поиска `_review/**/*.md`.

- **Если пусто** → сообщи: «_review/ пуста — раскладывать нечего.» → Стоп.

Для каждого найденного файла определи:

1. **Целевую папку** — из frontmatter-поля `folder:`; если поля нет — из подпапки пути (`_review/08_ИТ/Заметка.md` → `08_ИТ`). Если не определяется ни так, ни так — пометь «целевая папка неизвестна» (решит пользователь в плане).
2. **Действие** — если в целевой папке уже лежит файл с тем же именем → **заменить** (это обновление существующей заметки, одобренное ранее при записи в `_review/`); если нет → **создать**.

---

## Шаг 2. План раскладки (Plan Mode)

Покажи план таблицей:

| Файл в _review/ | Целевая папка | Действие |
|---|---|---|
| … | … | создать / **заменить** |

Замены выдели отдельным блоком — это перезапись оригиналов, пользователь должен их увидеть явно. Файлы с неизвестной целевой папкой — отдельным списком с вопросом «куда?».

Дождись approve плана. Без approve ничего не переноси.

---

## Шаг 3. Исполнение переноса — это ПЕРЕНОС ФАЙЛА, не генерация

⚠️ **Критично: ты ПЕРЕМЕЩАЕШЬ файл, а НЕ сочиняешь заметку заново.** Пользователь МОГ вручную отредактировать заметки в `_review/` после их создания (поправить формулировки, факты, что угодно) — именно для этого `_review/` и существует. **Его версия на диске — единственный источник истины и финальная.**

Категорически ЗАПРЕЩЕНО воспроизводить содержимое заметки из своей памяти/контекста (из того, что ты генерировал на шаге `process-transcript` ранее в этой же сессии) — даже если «помнишь», каким был текст. Если эти заметки есть у тебя в контексте от прошлого прогона — ИГНОРИРУЙ контекст, бери ТОЛЬКО то, что прямо сейчас лежит в файле. Воспроизведение из памяти затрёт правки пользователя — это потеря данных.

Для каждого файла из плана:

1. **Прочитай файл `Read`-инструментом ПРЯМО СЕЙЧАС** — возьми его ТЕКУЩЕЕ содержимое с диска дословно. Это и есть то, что переносится.
2. Примени к прочитанному содержимому РОВНО ДВЕ механические правки, не трогая больше НИЧЕГО (ни слова, ни факта, ни структуры, ни порядка):
   - убери из frontmatter строку `folder:` (служебная метка ревью);
   - разверни ревью-хайлайты: каждый `==текст==` → `текст`.
   Остальной frontmatter (`source_type`, `source`, `created`, `modified`) и всё тело — байт в байт как в файле. `modified` НЕ обновляй (перенос ≠ правка).
3. Запиши результат в `<целевая папка>/<имя файла>` (поверх существующего, если действие «заменить»).
4. **Сверка перед удалением.** Убедись, что записанный файл содержательно идентичен исходнику из `_review/` (минус снятые `folder:` и `==`): тот же текст, те же факты, те же правки пользователя. Только файл, прошедший сверку, можно удалять на Шаге 4. Если содержимое разошлось — это потеря данных: перезапиши цель из исходника и НЕ удаляй исходник, пока не совпадёт.

---

## Шаг 4. Очистка _review/

Удали из `_review/` ТОЛЬКО те исходники, чья цель прошла сверку на шаге 3.4 (записана и содержательно совпала). Удаляй **одной батч-командой** (не по одному файлу — чтобы не дёргать пользователя серией подтверждений). Опустевшие подпапки `_review/<NN_*>/` удали той же командой. Файлы, которые не раскладывались (неизвестная папка, пользователь отложил) или не прошли сверку, — НЕ трогай.

---

## Шаг 5. Финальный отчёт

```
✓ Раскладка завершена

Создано: N заметок → [список папок]
Заменено (обновления существующих): M заметок → [список папок]
Снято folder-меток: N+M, ревью-хайлайтов: K
_review/ очищена.
```

Если остались файлы с неизвестной целевой папкой — перечисли их и спроси, куда раскладывать (или оставить в `_review/`).
